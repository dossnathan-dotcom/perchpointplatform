# Phase 1 Governance

This directory is the operational index for PerchPoint governance. Normative requirements live
in `REQUIREMENTS_TRACEABILITY.md`; product identity lives under `docs/product`; source
provenance lives under `docs/source`; independent evidence lives in
`docs/audits/PHASE_0_CURSOR_AUDIT.md`.

- `APPROVED_DECISION_REGISTER.md` maps every material approved decision to requirements,
  policy, ownership, verification, and acceptance.
- `PLATFORM_VISION_TRACEABILITY.md` maps authoritative PDF page detail to existing atomic
  requirements without duplicating them.
- `NORMATIVE_COVERAGE.md` classifies each governance artifact and maps its normative content.
- `PHASE_1_ACCEPTANCE.md` records current evidence and blockers.
- [Phase 2 planning package](../plans/phase2/README.md) is planning only until Nathan
  approves it.
- [Phase 5 canonical data package](../plans/phase5/README.md) defines the current PostgreSQL,
  RLS, search, storage, export, and data-governance substrate.
- [Phase 6 identity and access package](../plans/phase6/README.md) maps approved Q1–Q160
  identity, authorization, delegation, workforce, security, UI, and verification decisions.
- [Phase 6 answer traceability](../plans/phase6/ANSWER_TRACEABILITY.md) names source answers,
  implementation, tests, owners/authorities, assumptions/dependencies/risks, stable
  requirements, and evidence status for every Q1–Q160 decision.
- [Phase 6 execution ledger](../plans/phase6/EXECUTION_LEDGER.md) retains local, hosted,
  stakeholder, and production gates separately.

Acceptance is provisional wherever a named business or specialist decision remains open.
Phase 6 local technical acceptance is not granted; hosted, stakeholder, and production gates
remain `BLOCKED_EXTERNAL`.
