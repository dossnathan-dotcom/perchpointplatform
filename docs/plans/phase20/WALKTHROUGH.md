# Phase 20 walkthrough

Sign in with the synthetic demo accounts. This walkthrough does not use a real
phone, a real supplier, or a real location.

1. As the resident, open Report a problem. Read the safety sentence first. Submit
   a drip without a photo. My requests shows Received. It does not say someone is
   on the way.
2. As operations, open Maintenance. The same request is in the queue. Review it.
   The status becomes Reviewed. That is not a completed repair.
3. Propose the job to the technician. As the technician, open My jobs, accept it,
   and record the exact part. Start time, then stop time without a photo.
4. As operations, choose a different part and record the reason. The original
   specification remains visible. If the arrival does not match, the technician
   records the mismatch. The job stays not ready.
5. As the owner, open the briefing. The blocked job and the queue count come from
   the same cases. Open the case from the link.
6. Add a before photo and an after photo, then submit completion. A different
   person verifies it. Work completed appears only after that review.
7. Emergency practice: submit an immediate-danger report. The safety message
   returns without a photo. If the first notification is marked failed, the worker
   process advances the escalation. The resident is not told the notification was
   acceptance.

Location check-in uses the browser only after the Check in location button, and
only on a secure page. A phone opened over plain HTTP cannot use location.
Localhost emulation is not physical-device acceptance.

Coverage in this phase is synthetic. It is not a claim of real 24/7 response.
